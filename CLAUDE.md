# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

This repository contains tools and scripts for synchronizing health data between Samsung Health and Google Fit, as well as utilities for preparing Google Takeout data for import into Apple Health and exporting data from Apple Health. The primary purpose is to export Samsung Health data to Google Fit and read it back, leveraging the Google Fitness API.

## Directory Structure

- `raw_exports/google_fit/` and `raw_exports/google_health/`: Google Takeout data exports (JSON and CSV).
- `raw_exports/samsung_health/`: Directory to place Samsung Health export CSV files (expected structure: subdirectories like `com.samsung.shealth.<category>/` with CSV files).
- `apple_health_import/`: Output directory for CSV files prepared for Apple Health import (generated by `prepare_apple_health_data.py`) or imported from Apple Health (via iOS app).
- `ios_app/`: iOS application for reading data from Apple Health (HealthKit) and exporting CSV files compatible with `apple_health_import/` format.
- `scripts/`:
  - `push.py`: Uploads Samsung Health data to Google Fit.
  - `read.py`: Reads data from Google Fit and outputs a daily summary.
  - `prepare_apple_health_data.py`: Converts Google Takeout data (Fit and Google Health) into Apple Health-compatible CSV files.
  - `setup.sh`: Sets up a Python virtual environment and installs dependencies.
- Configuration files:
  - `credentials.json`: OAuth 2.0 client secret (required for Google Fitness API access).
  - `token.pickle` and `token_read.pickle`: Persisted OAuth tokens for push and read operations.
  - `uploaded_dates.json`: Tracks dates already uploaded to avoid re-upload.
  - `requirements.txt`: Lists Python dependencies.
  - `health_sync.egg-info`: Package metadata (generated by setup).

## Setup and Installation

1. **Obtain OAuth credentials**:
   - Create a Google Cloud project with the Fitness API enabled.
   - Create an OAuth 2.0 Client ID (Desktop app) and download the JSON to `credentials.json`.
   - Add your Google account as a test user if the consent screen is in testing mode.

2. **Install dependencies**:
   ```bash
   ./setup.sh
   ```
   This creates a virtual environment (`.venv`) and installs required packages.

3. **Activate the virtual environment** (required before running scripts):
   ```bash
   source .venv/bin/activate
   ```

4. **Prepare your data**:
   - Export your Samsung Health data and place the CSV files inside `raw_exports/samsung_health/` preserving the folder structure (see README.md for expected subdirectories).
   - Place your Google Takeout data (from Google Fit and Google Health) in `raw_exports/google_fit/` and `raw_exports/google_health/` respectively.

## Common Commands

### Data Synchronization

- **Push Samsung Health to Google Fit**:
  ```bash
  python scripts/push.py
  ```
  Reads CSV files from `raw_exports/samsung_health/` and uploads steps, distance, calories, weight, body fat, hydration, sleep, and heart points to Google Fit.
  Subsequent runs skip already-uploaded dates using `uploaded_dates.json`.

- **Read data from Google Fit**:
  ```bash
  python scripts/read.py                     # last 30 days
  python scripts/read.py 2025-01-01          # from start date to today
  python scripts/read.py 2025-01-01 2025-12-31  # explicit date range
  ```
  Outputs a daily table with steps, distance, calories, heart points, and sleep, plus latest body metrics.

### Data Preparation (Google Takeout → Apple Health)

- **Prepare Google Takeout data for Apple Health import**:
  ```bash
  python scripts/prepare_apple_health_data.py
  ```
  Reads data from `raw_exports/google_fit/` and `raw_exports/google_health/` and writes Apple Health-compatible CSV files to `apple_health_import/`.

### Data Export (Apple Health → Local)

- **Export data from Apple Health using iOS app**:
  1. Open `ios_app/` in Xcode
  2. Configure signing with your Apple ID
  3. Build and run on iPhone
  4. Grant HealthKit permissions when prompted
  5. Select date range and fetch data from Apple Health
  6. Export to CSV files in app's Documents directory
  7. Transfer exported CSV files to `apple_health_import/` directory
  See `ios_app/README.md` for detailed instructions.

## Tips for Working with This Data

- CSV files in `raw_exports/google_fit/daily_activity_metrics/` contain 15-minute interval data with various metrics.
- JSON files in `raw_exports/google_health/global_export_data/` typically contain arrays of objects with timestamp-value pairs.
- Timestamps are often in ISO 8601 format with timezone offsets.
- When analyzing, consider merging data from multiple dates for time-series analysis.
- Be aware of missing values (empty fields) in CSV data.
- The `scripts/prepare_apple_health_data.py` script can be used to generate Apple Health-importable CSV files from Google Takeout.
- The iOS app in `ios_app/` exports CSV files in the same format as `prepare_apple_health_data.py` for seamless integration.

## Notes

- There is no traditional build, lint, or test suite for the core Python scripts; the value lies in the data and the provided scripts.
- The iOS app requires Xcode 11.0+ and an iPhone running iOS 8.0+ to build and run.
- The scripts rely on the Google Fitness API; ensure the API is enabled and OAuth credentials are correctly configured.
- First execution of `scripts/push.py` or `scripts/read.py` will open a browser window for Google sign-in and consent.
- Tokens are stored in `token.pickle` (push) and `token_read.pickle` (read) and are automatically refresced when expired.
- The `raw_exports/` directory separates raw exported data from processed output (`apple_health_import/`).
- If you create additional scripts or derived files, consider adding them to `.gitignore` to avoid committing sensitive or generated content.
- This CLAUDE.md is intended to help future instances of Claude Code quickly understand how to work with this health data synchronization repository.
