This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

This repository contains tools and scripts for synchronizing health data between Samsung Health and Google Fit, as well as utilities for preparing Google Takeout data for import into Apple Health and exporting data from Apple Health. The primary purpose is to export Samsung Health data to Google Fit and read it back, leveraging the Google Fitness API.

## Directory Structure

- `raw_exports/google_fit/` and `raw_exports/google_health/`: Google Takeout data exports (JSON and CSV).
- `raw_exports/samsung_health/`: Directory to place Samsung Health export CSV files (expected structure: subdirectories like `com.samsung.shealth.<category>/` with CSV files).
- `apple_health_import/`: Output directory for CSV files prepared for Apple Health import (generated by `prepare_apple_health_data.py`) or imported from Apple Health (via iOS app).
- `ios_app/`: iOS application for reading data from Apple Health (HealthKit) and exporting CSV files compatible with `apple_health_import/` format.
- `scripts/`:
  - `push.py`: Uploads Samsung Health data to Google Fit.
  - `read.py`: Reads data from Google Fit and outputs a daily summary.
  - `prepare_apple_health_data.py`: Converts Google Takeout data (Fit and Google Health) into Apple Health-compatible CSV files.
  - `setup.sh`: Sets up a Python virtual environment and installs dependencies.
- Configuration files:
  - `credentials.json`: OAuth 2.0 client secret (required for Google Fitness API access).
  - `token.pickle` and `token_read.pickle`: Persisted OAuth tokens for push and read operations.
  - `uploaded_dates.json`: Tracks dates already uploaded to avoid re-upload.
  - `requirements.txt`: Lists Python dependencies.
  - `health_sync.egg-info`: Package metadata (generated by setup).
- Utility scripts (for iOS project maintenance):
  - `*.py` scripts in root: Various Xcode project fixing utilities

## Setup and Installation

1. **Obtain OAuth credentials**:
   - Create a Google Cloud project with the Fitness API enabled.
   - Create an OAuth 2.0 Client ID (Desktop app) and download the JSON to `credentials.json`.
   - Add your Google account as a test user if the consent screen is in testing mode.

2. **Install dependencies**:
   ```bash
   ./setup.sh
   ```
   This creates a virtual environment (`.venv`) and installs required packages.

3. **Activate the virtual environment** (required before running scripts):
   ```bash
   source .venv/bin/activate
   ```

4. **Prepare your data**:
   - Export your Samsung Health data and place the CSV files inside `raw_exports/samsung_health/` preserving the folder structure (see README.md for expected subdirectories).
   - Place your Google Takeout data (from Google Fit and Google Health) in `raw_exports/google_fit/` and `raw_exports/google_health/` respectively.

## Common Commands

### Data Synchronization

- **Push Samsung Health to Google Fit**:
  ```bash
  python scripts/push.py
  ```
  Reads CSV files from `raw_exports/samsung_health/` and uploads steps, distance, calories, weight, body fat, hydration, sleep, and heart points to Google Fit.
  Subsequent runs skip already-uploaded dates using `uploaded_dates.json`.

- **Read data from Google Fit**:
  ```bash
  python scripts/read.py                     # last 30 days
  python scripts/read.py 2025-01-01          # from start date to today
  python scripts/read.py 2025-01-01 2025-12-31  # explicit date range
  ```
  Outputs a daily table with steps, distance, calories, heart points, and sleep, plus latest body metrics.

### Data Preparation (Google Takeout → Apple Health)

- **Prepare Google Takeout data for Apple Health import**:
  ```bash
  python scripts/prepare_apple_health_data.py
  ```
  Reads data from `raw_exports/google_fit/` and `raw_exports/google_health/` and writes Apple Health-compatible CSV files to `apple_health_import/`.

### Data Export (Apple Health → Local)

- **Export data from Apple Health using iOS app**:
  1. Open `ios_app/` in Xcode
  2. Configure signing with your Apple ID
  3. Build and run on iPhone
  4. Grant HealthKit permissions when prompted
  5. Select date range and fetch data from Apple Health
  6. Export to CSV files in app's Documents directory
  7. Transfer exported CSV files to `apple_health_import/` directory
  See `ios_app/README.md` for detailed instructions.

### iOS App Development

- **Build and run iOS app**:
  ```bash
  # From ios_app/ directory
  xcodebuild -scheme HealthImportApp -destination 'platform=iOS Simulator,name=iPhone 14,OS=latest' build
  ```
  Or open the project in Xcode and use the standard build/run workflow.

- **Clean iOS app build**:
  ```bash
  # From ios_app/ directory
  xcodebuild clean
  ```

### Utility Scripts

The repository includes several utility scripts for maintaining the Xcode project:
- `fix_info_plist_buildfile.py`: Fixes Info.plist build file references
- `fix_project_*.py`: Various project fixing utilities
- `cleanup_duplicates.py`: Removes duplicate files from project
- `validate_pbxproj.py`: Validates the project.pbxproj file
- `test_plist.py`: Tests property list file loading

These utilities are typically run when encountering Xcode project issues:
```bash
python fix_info_plist_buildfile.py
python fix_project_final.py
```

## Data Architecture

### Samsung Health to Google Fit Flow
1. Samsung Health exports CSV files with specific naming patterns
2. `push.py` parses these files (handling two-row headers and timestamp formats)
3. Data is uploaded to Google Fit using the Fitness API with custom data sources
4. `uploaded_dates.json` tracks uploaded dates to prevent duplicates

### Google Takeout to Apple Health Flow
1. Google Takeout JSON/CSV files are placed in `raw_exports/google_*`
2. `prepare_apple_health_data.py` converts these to Apple Health-compatible CSV format
3. Output files are written to `apple_health_import/` directory
4. These files can be imported into Apple Health or used by the iOS app

### Apple Health to Local Export Flow
1. iOS app reads data from HealthKit using requested permissions
2. Data is fetched for specified date ranges
3. Exported CSV files match the format expected by repository tools
4. Files are transferred to `apple_health_import/` for further processing

## Development Guidelines

### Python Scripts
- All Python scripts require the virtual environment to be activated
- Scripts use OAuth 2.0 for Google Fitness API authentication
- Tokens are automatically refreshed when expired
- Error handling includes specific guidance for common OAuth issues
- CSV parsing handles Samsung Health's unique two-row header format

### iOS App
- Built with SwiftUI and HealthKit framework
- Follows MVVM-like architecture with separate views, models, and services
- HealthKit interactions are encapsulated in `HealthKitManager.swift`
- Data export functionality is in `DataExportService.swift`
- UI logic is in `HealthDataView.swift` and `HealthImportApp.swift`

### Virtual Environment
- Always activate the virtual environment before running Python scripts:
  ```bash
  source .venv/bin/activate
  ```
- To deactivate when done:
  ```bash
  deactivate
  ```
- To reinstall dependencies if needed:
  ```bash
  pip install -r requirements.txt
  ```

## Troubleshooting

### Common Issues and Fixes

| Error | Fix |
|-------|-----|
| `Error 403: access_denied` | Add your Google account as a test user on the OAuth consent screen |
| `Cannot read data of type com.google.step_count.delta` | Run `python scripts/push.py` first to create the data source |
| `The caller does not have permission` | Verify Fitness API is enabled and account is a test user |
| `Unable to fetch DataSource` | Re-run the script; if persistent, check API enablement |
| Xcode build failures | Run the appropriate `fix_project_*.py` script |
| Missing HealthKit data in simulator | Use a physical device for reliable HealthKit testing |

### Data-Specific Tips
- CSV files in `raw_exports/google_fit/daily_activity_metrics/` contain 15-minute interval data
- JSON files in `raw_exports/google_health/global_export_data/` contain timestamp-value pairs
- Timestamps are typically in ISO 8601 format with timezone offsets
- For time-series analysis, consider merging data from multiple dates
- Be aware of missing values (empty fields) in CSV data
- The `scripts/prepare_apple_health_data.py` script generates Apple Health-importable CSV files
- iOS app exports CSV files in the same format as `prepare_apple_health_data.py` for seamless integration

## Best Practices

1. **Always work in the virtual environment** when running Python scripts
2. **Preserve the Samsung Health directory structure** when placing export files
3. **Verify OAuth setup** before running scripts for the first time
4. **Check `uploaded_dates.json`** to understand what data has been uploaded
5. **Use physical iOS devices** for reliable HealthKit testing (simulator has limited data)
6. **Keep credentials.json secure** and never commit it to version control
7. **Run utility scripts** only when encountering Xcode project issues
8. **Back up token files** (token.pickle, token_read.pickle) if migrating environments
